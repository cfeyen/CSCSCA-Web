Rules

A standard rule is written as follows:


The input and output of a rule are made up of phones. Phones are made up of characters not separated by whitespace like a, á, ts, and a_phone.

Each character in the input is considered to be a phone.

An input achȍ becomes the phones a, c, h, and ȍ.

Note: the diacritic, \u{030F}, remains attached to the o as any¹ unicode combining characters will be combined with the proceeding base character.

producing the phones a, tʃ, and ȍ.


Note: A line starting with ## is a comment and is ignored when applying rules.


The shift token >> may also be replaced with a few alternatives.

  • >>: The rule applies left-to-right and does not try to reapply on every set of phones replaced

  • >: The rule applies left-to-right and tries to reapply on every set of phones replaced

  • <<: The rule applies right-to-left and does not try to reapply on every set of phones replaced

  • <: The rule applies right-to-left and tries to reapply on every set of phones replaced


There are also some special characters that represent phones.

  • #: represents a word boundary

  • *: represents any phone except a word boundary

Conditions

A rule may also be given a condition starting with /.

A rule may be given more than condition one and applies if any of them succeeds.

If two or more conditions must match for a rule to apply, start all conditions after the first with &.

If &! is used instead, all following subconditions must fail for the condition to be able to succeed.

Note: & and &! are right associative.


A condition must contain a _ separated from other phones by whitespace.

Any phones before the _ must exist before the input and any phones after the _ must exist after the input for a condition to succeed.


A rule may also be have anti-conditions which follow conditions and start with //.

A rule does not apply if any anti-condition succeeds.


Scopes

Scopes are a way to dynamically represent phones.


Selection Scopes

A selection scope is a comma-separated list of sets of phones encloded in curly braces ({ and }).

A selection scope represents one of the sets of phones inside.


Optional Scopes

An optional scope is a sets of phones encloded in parenthesis (( and )).

An optional scope represents either the phones it contains or nothing.


Repetition Scopes

A repetition scope is a sets of phones encloded in square brackets ([ and ]).

A repetition scope represents the contained set of phones repeated 0 or more times.

To limit the number of possible repetitions, a repetition scope may be ended with = followed by the minimum number of repetition and optionally followed by a comma and the maximum number of repetitions.

Note: repetitions cannot be put in the input or output of a rule.



Labels

Scopes and the * token try to agree across input and output.

However this may lead to unintended behavior as in the example bellow where the first scope in the input agrees with the first scope in the output.

To fix this, scopes (and *) can be prefixed with a label that starts with $.


Labels cause selections to agree in which subgroup they select, optionals in if their content is required, repetitions in maximum length², and * in which phone is required.


Labels can also cause agreement in conditions as well.
